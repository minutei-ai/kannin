# API

This page documents Kannin’s current native API. Public namespace listing and cache-warm hints also expose their Turbopuffer response shapes; the remaining native operations use different contracts. Full compatibility is required but not implemented. See the [compatibility contract and gaps](turbopuffer-contracts.md).

HTTP failures return `{"status":"error","error":"message"}` with the numeric HTTP status preserved. Backend failures use a sanitized message; the administrative namespace listing also maps native/validation failures to a private, non-cacheable 503 response. Native binding failures retain the existing typed `RpcReply`/`Rejected` contract.

`GET /health` is public. `snapshotR2Reads` counts snapshot acquisition attempts and `snapshotSharedReads` counts joins to pending acquisitions in the responding isolate. These diagnostic counters are process-local, not global Cloudflare request counts or persistence guarantees. All namespace operations require `Authorization: Bearer <token>`.

```sh
curl "$RAIO_URL/v1/namespaces/example/write" \
  -H "Authorization: Bearer $RAIO_API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"requestId":"batch-1","schema":{"filterable":["year"],"vectorFilterFields":["year"]},"upserts":[{"id":"one","title":"Cloudflare search","text":"Rust, R2 and Durable Objects","attributes":{"year":2026}}],"deletes":[]}'

curl "$RAIO_URL/v1/namespaces/example/query" \
  -H "Authorization: Bearer $RAIO_API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"kind":"text","text":"cloudflare rust","match":"any","topK":10,"filters":[{"field":"year","op":"gte","value":2026}]}'
```

- `GET /v1/namespaces`: authenticated public listing with optional `prefix`, `page_size` (1–1,000, default 100) and opaque `cursor`. Returns `{ "namespaces": [{ "id": "example" }], "next_cursor": "..." }`, omitting the continuation when complete. Preserve the prefix when continuing; cursors are bucket/prefix scoped. A page can contain fewer items than requested when R2 truncates it. Responses are private/no-store. Listing returns 503 until migration completes, or when catalog data is malformed; it does not silently omit corrupt entries. Namespace names accept the documented ASCII alphabet and up to 128 characters, including embedded/leading dots. Dot-segment names `.` and `..` remain rejected because URL normalization changes their routing; the single administrator token also differs from permission roles. The expanded identity cases await the full gate.
- `GET /v1/namespaces/:name/hint_cache_warm`: acknowledges an asynchronous immutable-directory warming hint with HTTP 202 and `{ "status": "ACCEPTED", "message": "cache warm hint accepted" }`. Requires an existing namespace and the same bearer authorization. Work deduplicates by bucket/namespace within a runtime, with at most four tasks. Each task considers at most 64 newest eligible segment headers, skips headers above two MiB, admits at most 16 MiB in total and has a nominal 20-second deadline. It uses existing bounded immutable caches, retains a reader pin through the task, and never changes the canonical Root or sequence. It is an advisory hint, not a guarantee of full cache residency or latency. Missing namespaces return 404; exhausted task admission returns 503. Responses are private/no-store.
- `POST /v1/namespaces/:name/write`: atomic upserts/deletes, optional `reset: true`, durable request-id receipts. Reusing an id with another payload returns 409.
- `POST /v1/namespaces/:name/migrate-root`: send `{}` to convert stored Root v1–v4 manifests, rebuild checkpoints and legacy segments to StoredRoot v5/RAIOSEG2. Returns `version: 5`, `sequence`, `rootRewritten`, `migratedSnapshots` and `expiredSnapshots`. Checkpoints convert first; Root activates through its captured ETag last. Source segment objects, logical search state and absolute checkpoint expiry are preserved; converted segment keys and common-leader offsets change. V4 Bloom pack bytes are reused with remapped segment references. Versions 1/2 derive eligibility; versions 3/4 preserve existing models. ETag conflicts return 409 and allow retry. Oversized converted segments or checkpoints fail before their manifest/checkpoint CAS. Ordinary reads require the converted format.
- `POST /v1/namespaces/:name/vector-rebuild`: validate canonical vectors and warm immutable structures from a persisted Root snapshot of at most eight MiB, in pages of at most 100 rows. Return the snapshot/segment/row cursor unchanged to resume. No external index is built.
- `POST /v1/namespaces/:name/query`: `text`, `vector`, or `hybrid`; required `topK` and `filters`. Text matching supports `any`, `all`, and `phrase`. Any/all accept at most 512 distinct normalized terms; phrases accept at most 64 normalized tokens. Text input remains limited to 8,192 characters. A vector query supplies finite float32-range numbers with nonzero float32 magnitude. Its length must equal the namespace's `schema.vectorDimensions` (1–10,752), defaulting to 768 for existing and unconfigured namespaces; mismatched writes and queries return 400. Hybrid supplies both text and vector. Text top-k is capped at 100; vector/hybrid top-k currently remains capped at 50 by the native API schema.
- `GET /v1/namespaces/:name/metadata`: manifest document count, committed sequence, and pending vector outbox count. Includes WASM capacity and cache counters. `cache.directoryCommonHits` counts acquisitions of projected directory handles, not queries or removed filter predicates. `encodedDirectoryCacheChargedBytes` includes `encodedDirectoryAdmissionChargedBytes`; subtract admission tracking to obtain the compressed-frame charge.
- `POST /v1/namespaces/:name/vector-sync`: validate up to sixteen committed vector outbox jobs and acknowledge them only after canonical live payload checks succeed. Background dispatch also processes these jobs. The response contains `submitted` (0–16 processed jobs) and `visibility: "strong"`; vector query visibility already follows the committed Root.
- `POST /v1/namespaces/:name/rebuild`: reloads the R2 manifest and fills missing bounded common-term prefixes, constant-attribute summaries and minimum-length document indexes from canonical segment headers, one segment at a time. It commits only manifest metadata through the existing conditional R2 write, preserving the sequence and immutable segments. Repeating a completed rebuild does not rewrite the root. No database replay is needed.
- `POST /v1/namespaces/:name/collect`: scans up to 100 R2 segments per page. Send `{}` initially and then `{ "cursor": "..." }` until the returned cursor is null. Unreferenced segments require a 24-hour quarantine measured from their first unreferenced observation. Active roots and rebuild checkpoints pin segments; checkpoints expire at their absolute expiresAt R2 metadata deadline, initially seven days after creation, and an expired rebuild cursor returns 410. Logs and idempotency receipts remain durable indefinitely.
- `POST /v1/namespaces/:name/compact`: coalesces up to eight small segments within a 10,000-document / 8 MiB decoded-document window, dropping tombstoned rows and retaining original document revisions. A candidate that would exceed the decoded-byte budget is left intact; any rows tentatively read from it are discarded from the new segment. Other complete candidates can still merge, and an ineligible window returns a no-op rather than repeatedly failing with 413. The new segment is activated by manifest CAS. Native Cloudflare Queues schedule bounded compaction on the existing sixteen-write cadence when segment counts exceed `max(4, 2 × ceil(documents / 10000))`. Merge size and decoded-byte limits still apply; large documents can prevent reaching that target.

Attributes accept scalars and flat scalar arrays of up to 4,096 elements. Arrays retain their order and may contain strings, finite numbers, booleans or null, including mixed values; nested arrays and objects are rejected. They are preserved through queries, replacement, compaction and rebuild. Constant-attribute proofs remain scalar-only, and unsupported eligibility models fall back to canonical masks. This extension awaits the complete gate. The public typed-array schema and wire contracts remain unimplemented.

Filters are ANDed. Supported operators are `eq`, `ne`, numeric `gt/gte/lt/lte`, `in`, `exists`, and array membership `contains/notContains/containsAny/notContainsAny`. Membership uses exact scalar equality without coercion; it does not search substrings. `containsAny` accepts up to 32 values; an empty list matches no rows. Negative membership is the logical inverse, including for missing, null and non-array attributes. Membership applies before text/vector top-k in Rust. These new operators await the complete gate. Booleans, numbers, strings, JSON null, and absent properties are distinguished. Rust applies the same exact filters and tombstones before text and vector top-k. Declare up to 64 scalar attribute names in `schema.filterable` on a write. The legacy ordered `vectorFilterFields` subset of at most five names is retained for schema/checkpoint compatibility, but does not limit native filter evaluation or configure provider indexes. Both lists reject duplicates. Omitted schema means no attributes are filterable. Queries referencing undeclared fields return 400 for all query kinds. Metadata returns the persisted schema or null.

The optional `schema.vectorDimensions` configures the one dense vector column. Changing it requires reset, including when an existing namespace uses the implicit 768-dimensional default. Old request receipts remain replayable after a dimension-changing reset without replaying their mutations. This new dimension contract awaits the complete gate.

The schema can be supplied with the first document batch or with a schema-only write (`requestId`, `schema`, `upserts: []`, `deletes: []`). Later writes may omit it. A different schema requires `reset: true` and reimporting the documents; reset and schema commit atomically. All declared filterable fields use exact native masks over canonical segment attributes before selection. No provider metadata slots, scalar hashes, external candidate cap or post-selection residual filtering is required. Persisted per-attribute inverted indexes remain a separate optimization.

For an existing namespace without a schema, explicitly submit a schema-only write with the desired fields. This increments the sequence and rotates the vector epoch so old slot meanings cannot affect new queries. Native queries use the canonical vectors immediately; `vector-rebuild` validates and warms the selected canonical epoch without controlling query visibility. There is no automatic inference from stored attributes or from the previous deployment variable. Use the write sequence as `minimumSequence` when an edge query must observe the newly configured schema.

Configured writes and compaction copy only `schema.filterable` attributes into segment headers. Complete attributes remain in R2 document payloads and returned rows. Unconfigured writes retain full header attributes so a later first schema-only write can enable existing fields without a backfill. Existing full headers remain valid; eligible compaction or reset/reimport applies the projection. A healthy single segment remains a compaction no-op.

Rust also produces bounded eligibility models from those declared fields. StoredRoot pools each model once; it covers query subsets without indexing undeclared attributes. A model is limited to 4 KiB and 256 groups/cells; unsupported or high-cardinality data stores null and uses canonical catalogs. These facts bound segment scores, while the ranker still applies exact filters and tombstones before top-k. They are internal metadata, not client-supplied query proofs.

Full-text BM25 currently indexes the fixed `title` and `text` document fields. Arbitrary named full-text attributes and per-attribute BM25 queries are not implemented; declaring a filterable attribute does not enable full-text indexing for it.

Rust implements field-normalized BM25 with namespace-wide live document frequencies, title weight 2, body weight 1, `k1=1.2` and `b=0.75`. Posting blocks carry token positions and conservative score bounds; exact block pruning is checked against exhaustive scoring. Unicode words are lowercased and decomposed with combining marks removed; CJK word boundaries currently produce character tokens. No stemming, synonym expansion, or typo tolerance is claimed. Hybrid ranking uses reciprocal rank fusion with denominator `60 + rank`.

## Durability

A write stores an immutable Rust/WASM index segment and compressed log, atomically advances the R2 manifest with an ETag precondition, then persists the receipt, ensures the namespace catalog entry is published, and submits any vector job. R2 is the source of truth. A failed response may follow a successful manifest commit; retry the same request id and payload. The manifest's last receipt repairs an interrupted acknowledgement without duplicating the write. Unreferenced segments and log objects are never queried.

Text reads default to strong consistency through the namespace coordinator. Text-only `consistency: "edge-eventual"` evaluates in the edge Worker using an R2 snapshot less than one second old at selection. Set `minimumSequence` to the sequence returned by a write for read-after-write: an insufficient snapshot is refreshed, and an uncommitted sequence returns 409. Snapshot age is bounded at selection, not at response delivery; slow storage can delay the response. Edge snapshot Cache API lookup has a nominal 250 ms budget and canonical acquisition a shared 900 ms budget before coordinator recovery. These are scheduling budgets, not hard response deadlines. Cache failures use fresh R2 reads and never serve expired snapshots. Vector and hybrid reads use exact native scoring over the captured canonical Root and report `strong`; they respect the same minimum-sequence barrier and need no asynchronous external-index visibility. Coordinator memory and immutable caches are disposable. Tombstones and filters apply before candidate selection, and resets select only the new canonical epoch.

See [architecture and remaining gates](architecture.md) and [the enforced static checks](lint.md).

Failed queries retain completed `Server-Timing` intervals and entered `text_phase` markers (`catalog`, `ranking`, `documents`, or `shared`). A 504 from the edge query’s 30-second lease can therefore identify the phase reached before timeout; intervals may overlap and do not measure CPU time. Snapshot acquisition precedes that lease.
