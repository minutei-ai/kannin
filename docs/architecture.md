# Architecture and completion gates

Kannin is a separate OSS repository. No Minutei production data, fixtures, secrets, or services are bundled.

## Cloud portability gates

### Native vector ownership (migration in progress)

Kannin owns vector indexing and search in its Rust engine, with canonical vectors and index structures in S3/R2. Native exact cosine queries scan separately addressable vector frames and apply filters/tombstones before bounded top-k. Rust breaks ties with the same UTF-16 document-ID comparator used by the existing text engine; TypeScript retains only selected locations. Synchronization validates live canonical vectors against committed logs before acknowledging jobs. Rebuild pages validate persisted vectors and warm immutable structures using durable, bounded snapshot cursors; they do not construct an ANN accelerator. Embedding generation belongs to the caller or an optional model provider, such as Workers AI. Vectorize and Qdrant runtime, provisioning and dependency-manifest entries have been removed. A passing full native-vector gate remains pending. Earlier external-vector evidence below is historical and does not validate this replacement.

Railway and Docker are the priority targets. The shared runtime is implemented in `src/core/application.ts` and `src/core/storage.ts`, with structural platform ports in `src/platform.ts`. `src/worker.ts` and `src/providers/cloudflare.ts` own the Cloudflare bindings. `runtime/main.ts` serves the same operations through Bun without importing Cloudflare runtime or provisioning code. Alchemy `2.0.0-beta.84` owns three selectable stacks under `infra/`, loaded lazily by `alchemy.run.ts`; Railway is the default. Native commands retain `--profile minutei`.

### Portable immutable cache

The portable `CacheProvider` is optional and provider-owned. Docker provisions a private Varnish-backed gateway whose TypeScript/Effect client implements the immutable `match/put/delete` subset used by the core. Cache identity includes endpoint/bucket scope, cache name and complete immutable object/version URL. Mutable Root/snapshot caches are denied. Public namespace authentication stays in the API, with a separate cache service credential checked before cache lookup. No user Authorization or cookies enter shared cache entries.

Varnish retains immutable bytes in a bounded malloc cache. Gateway staging and metadata are disposable bounded RAM; generation-fenced publication prevents stale fills from resurrecting deleted or replaced entries. Eviction, restart, invalid bytes or unavailable cache recover through canonical object storage. Container working files are bounded runtime cache metadata, never canonical documents, manifests, receipts or outboxes. Limits, transport details and the distinction from a geographically distributed CDN are documented in [the portable runtime](portable-runtime.md#self-hosted-immutable-cdn-cache). Cloudflare retains its native Cache API adapter. Complete gate and hosted proofs remain required.

### Provider independence and canonical state

`ObjectStore` is an Effect service for streaming/ranged reads, metadata, paginated listing, conditional publication and deletion. Its S3 adapter wraps the official AWS SDK and preserves native errors as causes. S3 metadata uses a base64 JSON envelope to retain Unicode and key casing. Logical keys escape literal percent and dot characters in their physical S3 representation, preserving prefix/delimiter operations and preventing dot-segment aliases. Transfer logical objects through the adapter when migrating; raw Cloudflare keys are not interchangeable with the escaped S3 representation. Buckets must support strongly consistent reads/listing and atomic If-Match/If-None-Match writes. Credentials and backend configuration stay outside the tracked tree.

All canonical documents, Rust segments, Roots, receipts, checkpoints and vector validation outboxes remain in object storage. No application database or volume is introduced. Rust owns text and vector scoring and filtering; vector queries no longer depend on derived external candidate indexes or provider visibility. Canonical frame checksums, dimensions, finite components and nonzero magnitudes are validated before scoring. Existing log deletion identities and the vectorFilterFields schema/checkpoint fields remain for compatibility; they do not select an external service.

Portable replicas reacquire the canonical Root before every operation. The exact observed object ETag fences manifest publication; a losing writer retries the same request only for the declared manifest-conflict failure. Content digests and unique attempt identities keep provisional portable logs, segments and Bloom packs immutable across competing attempts. This also fixes the initial-namespace retry race in which equal request IDs could otherwise overwrite logs with different vector epochs. The collector publishes a distinct optional `collectionFence` in the Root before scanning/deleting on the portable runtime, invalidating pending writers based on earlier Roots. Quarantine and checkpoint pinning remain required; collection fencing does not replace retention.

The portable queue is a bounded, process-local dispatch optimization. It deduplicates by namespace/job kind and retries failures; successful publication and restart recovery depend on canonical Roots, receipts and vector outboxes, not this queue. Startup and a periodic recovery scan rebuild the namespace catalog and redispatch pending vector jobs. Compaction is rediscovered from canonical segments. In-memory actor eviction, process restart and cache absence must not remove canonical state. The portable adapter uses the optional Varnish-backed HTTP cache when configured; existing bounded immutable caches inside the shared core remain in use. Strong reads never use manifest snapshot caches.

## Ownership

The Worker authenticates every namespace operation. Writes and default strong reads route to one volatile Durable Object coordinator. Explicit edge-eventual text reads select a bounded-age R2 snapshot and run the same Rust scorer in the edge Worker. If acquisition returns a snapshot outside that age budget or below the requested sequence, the original authenticated request routes to the coordinator, which validates the sequence against its current view. Expired snapshots never participate in ranking. Canonical edge snapshot acquisition has a nominal 900 ms shared budget. Readers joining the same in-flight root reuse its original outcome rather than starting another budget. A timeout or a full sixty-four-entry pending table recovers through the coordinator and reports `edge_snapshot_r2_timeout` or `edge_snapshot_r2_admission`. The original acquisition remains in `waitUntil` until its native body read settles; fully validated late bodies may enter the bounded memory cache only as expired payload/ETag candidates. They cannot serve queries or enter Cache API publication until a fresh canonical R2 read confirms their version. `snapshotLateRetentions` counts admitted candidates; it does not count cache publication or prove a latency improvement. A separate semaphore charges body acquisition and Schema decoding at four times object size, in 64 KiB units against a four-MiB target; an oversized individual body consumes every permit. Body admission never queues: a busy budget cancels the unused body and recovers through the coordinator with `edge_snapshot_r2_body_admission`. Headers arriving after the age budget may still consume and validate their body under the same admission quota when the object fits the candidate cache; oversized late headers and backwards-clock observations cancel their unread body. This can consume an additional late body read, but allows a later conditional R2 read to avoid downloading an unchanged manifest again. These quotas do not bound the whole Worker heap or guarantee native timer scheduling. This recovery can add the coordinator's network hop; its response carries request-local `edge_snapshot_fallback` timing. Canonical decoding/storage failures still fail, and an uncommitted future sequence still returns 409. Each object serializes mutations and strong-read manifest capture with an instance-owned Effect semaphore. Up to four strong queries run outside that semaphore after capturing an immutable root; queued readers capture only after admission. A read therefore observes its captured sequence even when a later reset or compaction commits. In-flight reader leases pin their segments during collection and release on success or failure. Collection enforces separate limits of 16,384 unique segment references and 16,384 unique Bloom pack references before deleting canonical objects. Query failures do not clear concurrent writer state. Failure responses retain completed query timings and request-local `text_phase` markers for catalog, ranking, document acquisition or a shared producer wait. These markers identify entered phases and do not establish CPU time. Worker timers advance only after I/O, so synchronous WASM phases can report zero despite consuming CPU; CPU profiles remain necessary for synchronous cost attribution. Response timings separate admission/coordinator wait (`query_wait`) from canonical root acquisition (`query_root`); neither establishes CPU use or network placement. Concurrent namespaces remain independent. The application never calls `ctx.storage` and never opens a local database. The coordinator caches the R2 manifest; all searchable data and recovery state belong to R2. Rust/WASM owns immutable index construction, positional postings, field-normalized BM25, exact block-bound pruning, filters, log compression, integrity checks and the shared text normalization used for both indexing and queries.

Benchmark samples retain `cf-placement` separately from ingress `CF-Ray`. The owning Alchemy Worker enables Smart Placement with `placement: { mode: "smart" }`. Cloudflare may relocate the default HTTP fetch handler after observing traffic; named catalog/segment entrypoints and Durable Objects retain their native placement contracts. The initial native experiment showed no relocation or latency improvement. Enabling the setting again does not establish a latency gain; comparisons must retain placement observations and native timings. See [Cloudflare placement](https://developers.cloudflare.com/workers/configuration/placement/).

Cloudflare's current [Durable Object location contract](https://developers.cloudflare.com/durable-objects/reference/data-location/) does not relocate existing objects when a hint changes. Its South America hint currently places objects in Eastern North America. Adding a `sam` hint therefore cannot remove the existing coordinator's international hop. Strong reads retain the coordinator contract; changing routing or replacing a coordinator requires separate correctness and native latency evidence.

Each coordinator also owns active text evaluations keyed by the captured manifest object and the complete Schema-encoded request, including text, match mode, top-k, filters, consistency and sequence barrier. Identical admitted text requests share the producer's row Promise while it runs. Each caller retains its own read lease, response encoding, sequence check and timings. Success and failure remove the entry; no completed query result is retained. Distinct roots, including same-sequence compaction, cannot join, and namespace ownership follows the coordinator instance. The existing four read slots bound active entries and retained request keys; these transient values are outside the immutable-cache quotas and do not establish peak-memory bounds. Followers report `text_inflight` wait time. Edge execution and vector/hybrid provider operations do not use this coordination.

Snapshot Cache API acquisition has a 250 ms foreground budget, including opening, matching and decoding. Concurrent readers with the same bucket, namespace and minimum sequence share that budgeted lookup until the underlying operation settles. A timeout uses canonical R2 and reports `edge_snapshot_cache_timeout`; `waitUntil` retains the outstanding native lookup. Late cache bodies must still pass the age and sequence checks, and cannot replace a newer sequence or a newer observation of the same sequence in memory. Background refresh after 250 ms of snapshot age remains independent of this lookup budget.

The internal snapshot Cache API namespace uses a versioned binary frame: eight magic bytes, a little-endian metadata length, a Schema-encoded observation timestamp/sequence and retained manifest JSON bytes. Canonical R2 manifests use StoredRoot v5; logical protocol.Root remains version 1. Common-term projections, dictionaries and declared-field eligibility models are pooled once. Each segment records the absolute end of its metadata column separately from its object size. Bloom bitsets remain in content-addressed packs with validated segment row references. Ordinary Root and rebuild-checkpoint reads accept v5 only. Authenticated migrate-root accepts stored v1–v4 through separate migration Schemas, publishes converted immutable segments, remaps common-leader ranges and Bloom segment keys, converts unexpired checkpoints through ETag preconditions first and commits Root last. Versions 1/2 derive eligibility once from converted canonical headers; versions 3/4 preserve existing models. Inline Bloom versions publish verified packs; v4 reuses pack bytes and digests. Sequences, document revisions, vector epochs, jobs and absolute checkpoint expiry survive conversion. Retries preserve already converted checkpoints. The existing unconditional stack hook runs before Vectorize metadata migration; its v5 Cloudflare execution remains unverified. Query initialization never migrates data. Snapshot caching uses KANSNP05, raio-snapshots-v5 and /snapshots-v5/{namespace}, so older frames miss and recover through R2. A fresh R2 body is decoded and validated once, retaining its original UTF-8 bytes for the frame instead of reserializing the complete manifest. An unchanged conditional R2 ETag reuses both the decoded manifest and retained payload. A retained per-entry timestamp groups Cache API publication attempts within 500 ms only for unchanged ETags; changed bodies publish immediately. Suppressed publications neither build a full payload Blob nor rewrite an older cached frame's observation time. Memory snapshots still use their own new canonical observation; every reader enforces the same one-second age and sequence barrier. Cache eviction or unsuccessful publication can leave other isolates with a miss until the next attempt; those readers recover through R2. Health reports isolate-local publication attempts, offered frame bytes and skipped publications, not storage receipts or billed usage. Cache readers validate framing, metadata, StoredRoot Schema, matching sequences and body age; HTTP metadata only rejects ineligible bodies before decoding. Corruption recovers through R2. The 24 MiB process LRU charges four times the larger of frame size and retained backing-buffer size, including payload views into a complete frame. Health reports charged bytes and retained payload buffers separately; these counters do not establish total Worker peak memory.

R2 owns canonical mutation logs, receipts, index segments and the atomic root. A write's sequence is assigned by the namespace coordinator. The segment and log are prepared before I/O and stored concurrently under separate immutable object keys. Both writes must complete successfully before a conditional root update. The root, rather than object listing, defines which documents committed. Receipt acknowledgement and queue submission follow that commit. Receipts use a conditional create; a collision reads and validates the existing receipt. The coordinator remembers only its last confirmed receipt to avoid repairing that same acknowledgement before every warm write. Losing this memory restores the canonical R2 repair path. A request may fail after committing in R2; retry the same request id and payload. The manifest retains the last receipt so an interrupted receipt write can be repaired before another mutation. Logs and idempotency receipts are retained indefinitely. Collection never deletes them, so request-id reuse keeps its original conflict/idempotency behavior; operators must budget this retained history.

Namespace enumeration has one canonical empty R2 record per committed namespace under `namespace-catalog-v1/{namespace}`. The first successful write acknowledgement follows Root commit, receipt persistence and catalog publication, in that order. Catalog creation uses an object precondition; retrying a failed publication repairs the already committed write without assigning another sequence. Successful publication is remembered by the disposable coordinator, avoiding repeated catalog I/O on warm writes. Orphan segment prefixes and no-op maintenance do not create entries. Listing reads one R2 catalog page, validates every key and zero-byte body size from list metadata, and never opens individual namespace Roots. It does not request custom metadata, which can reduce R2 pages to 100 objects despite a larger requested limit.

The existing unconditional RootFormatMigration backfills catalog entries for existing canonical Roots, including already-current v5 Roots, before completing activation through `/admin/namespaces/catalog`. This administrative operation writes the versioned zero-byte `namespace-catalog-v1.ready` marker. Public and binding listing fail closed with 503 until a first HEAD verifies that marker; successful readiness is memoized per native bucket binding. Requests never bootstrap or backfill the catalog. The current single API_TOKEN is administrator authority for all operations, including activation; the completion endpoint trusts that authority and does not independently repeat the inventory. Calling it before migration completes can expose an incomplete catalog. Permission-scoped customer keys are a remaining compatibility requirement. Deployment must retain this script ordering; its Cloudflare cutover and old in-flight writers remain unverified.

Malformed or missing catalog entries are repaired by migrate-root without rewriting an unchanged Root. External catalog deletion after acknowledgement is not automatically noticed by an actor that remembers successful publication; migration or actor recreation restores that path. No application flow deletes the readiness marker, and an already-ready isolate does not poll it again. Namespace deletion/recreation is not implemented. These constraints are separate from query-result caches and do not establish a cold/warm search latency improvement.

Native writes and compaction build RAIOSEG2/Header2 segments directly. The sixteen-byte envelope retains header length and CRC; compact JSON tuple positions follow the native Header field order. Named header_json metadata remains available. The payload contains adjacent metadata, raw little-endian float32 vector frames and positional postings. Document ranges address metadata only; dense vector ranges and a prefix index every 64 rows locate full vectors without duplicating a range on every document. Header loading validates framing, column partitions and posting bounds without inflating documents. Query materialization reads metadata only, aligns read-ahead relative to the payload start and clips it at the explicit metadata boundary. Logical window grouping tracks its sorted start, maximum end and selected-byte total incrementally, retaining the same page/span/hole limits. Singleton source groups need neither sorting nor a second window array; grouping still separates immutable key, header size, object size and metadata extent, and restores caller order by original index. Fresh ordered logical windows may share a request-local physical acquisition of at most 128 KiB, with at most 64 KiB aggregate overfetch. Fresh acquisitions selecting at least two pages may normalize their metadata-relative bounds to a clipped 128-KiB block, only when total overfetch stays within 64 KiB, the normalized span is at most four times the original span, and added padding is at most 16 KiB. Other acquisitions keep their exact bounds; single-page reads retain the existing 4-KiB policy. Stable physical keys enable Cache API reuse across query shapes without introducing another cache. Projection still runs in batches of at most sixteen pages; the direct readDocuments contract and native 64-KiB declared-decoded-byte limit remain unchanged. Physical buffers are not admitted to the process raw-buffer LRU. Selected frames are copied after validation; a cache fill during acquisition uses existing exact frames first and reads missing frames from the already acquired payload, avoiding additional R2 reads. The existing transport cache and query reader limits remain in effect. Eligible fresh windows project up to sixteen frames through one native serializer when declared decoded lengths total at most 64 KiB; larger selections keep scalar decoding. Fully cached windows also use that native batch for two to sixteen non-overlapping pages with at most 64 KiB compressed bytes. Each exact cached frame is acquired once; the transient packed buffer preserves caller order. When the native decoded-byte limit declines the batch, scalar projection reuses those acquired frames without a second cache lookup or hit count. No packed buffer or decoded document set is retained across calls; singleton, overlapping, partial-cache and larger compressed windows retain scalar projection. Each native metadata batch reuses one call-scoped zlib-rs Inflate and decompression scratch, after the existing aggregate decoded-byte guard. The inflater resets before each independent page; exact decoded length and frame CRC remain mandatory. Scratch capacity follows the largest page and never survives the call. After the aggregate guard, the JSON serializer reserves the declared decoded total plus 64 bytes per page and two delimiters as a capacity hint. The Vec can still grow normally; this is neither a new output limit nor a shared allocation. Scalar metadata readers release their decoded bytes before serialization or vector reconstruction. Successful batch projection and QueryDocument array validation precede per-page cache admission, so a corrupt selected sibling admits no partial set of pages through this path; existing raw-span caching is independent. Full reads join metadata and vector frames, including the prefetched compaction payload. Configured namespaces project header attributes to Root.schema.filterable while complete attributes remain in metadata and query rows.

The migration-only v1 reader copies existing postings and rebases offsets without tokenizing again. It preserves raw attribute JSON and exact float32 vector values. Converted objects use immutable keys derived from their bytes and original key; a failed conditional create verifies the existing body digest. Source objects remain until normal pinned/grace-period collection retires them. The converter rejects output beyond sixteen MiB. Checkpoint encoding rejects objects beyond eight MiB before creation or replacement; resume, migration and collection validate captured object sizes before reading bodies. Migration and collection additionally enforce a 32-MiB batch charge, including growth between listing, capture and conversion. These limits do not establish that every previously valid namespace fits the upgrade budget.

Canonical header parsing validates UTF-8 before the native JSON string reader; framing, CRC and structural checks remain required. Unescaped dictionary keys borrow the validated JSON until entering the dictionary’s owned text allocation; escaped keys retain Serde’s owned fallback. The WASM target enables `simd128` through the owning Cargo target configuration, and miniz uses its native SIMD Adler-32 backend. Internal directory acquisition uses the immutable `/directory-v5` cache resource and `RAIODIR5` frames. Rust validates the complete canonical header before encoding its native fields as unsigned varints and length-prefixed UTF-8 strings, retaining term dictionary keys and exact raw attribute JSON. Attribute encoding has an explicit inline/dictionary mode. Construction compares encoded byte costs and emits a sorted dictionary only when it is smaller; unique attributes retain inline encoding. Dictionary reads validate bounded counts, strictly sorted unique JSON values, every row reference and complete dictionary use before returning a Header. Values are immutable and shared only within the decoded directory. Decoded directories retain document IDs in one owned UTF-8 buffer with per-row ranges. The same DocumentMeta field contract projects borrowed IDs for serialization and lookup. Title/body lengths and vector presence live in constant/dense columns: uniform fields retain one value, while variable fields retain native vectors. Revision, ID ranges and data ranges remain in the row store; logical projections read the columns, and length-only scans consume them directly. Decoder admission charges a dense transition before reserving its full capacity. Retained accounting includes actual column capacities, and exact-budget decoding remains supported. Pool growth is charged before reservation, and retained accounting includes the pool capacity. Canonical segments and RAIODIR5/RAIOCOM3 wire formats remain unchanged. Decoded admission charges owned attribute values, row indexes and frequencies once. Dense attributes retain their owned values; dictionary attributes retain validated values, row indexes and frequencies rather than one shared handle per row. A separate checked expansion guard rejects logical attribute bytes above the declared canonical header length, including when structural validation is reusable. No read-time hash table, sampling or guessed cardinality is required. Directory inflation reserves the bounded declared compact length once and uses the `zlib-rs` fixed-slice decoder with Adler-32 validation enabled; its native status must be successful and the written length must match exactly. The binary decoder constructs the existing Header, DocumentMeta, TermMeta, BlockMeta and Range contracts directly; there is no second domain model. The twenty-byte frame prefix carries magic, canonical header length, compact decoded length and CRC. The CRC covers the first sixteen frame bytes and the decoded compact payload, protecting both declared lengths as well as content. Decoding checks the requested canonical length, caps the decoded body at both sixteen MiB and the original canonical header length, validates zlib integrity and CRC, rejects trailing bytes and applies the same header version, document ordering, frequency and block-directory validation as canonical reads. Rust retains immutable term entries as sorted ranges into one contiguous UTF-8 allocation and uses exact binary search for lookup. Binary decoding validates borrowed keys and ordering before assembling that allocation; its exact size and entry/block arrays are charged before allocation. Empty and multibyte keys preserve their boundaries. Canonical JSON parsing preserves unordered and escaped duplicate-key semantics through stable sorting and last-value deduplication. Binary frames require strictly sorted unique term keys. The binary decoder checks document, term and block counts against available input and the caller-owned decoded-memory quota before reserving arrays; strings, UTF-8, raw attribute JSON, flags and integer overflow remain validated. Canonical parsing releases unused document capacity; binary arrays reserve their validated counts exactly. Directory charging accounts for the retained slice, shared term text, document strings, blocks and document capacity against the existing quota. Smaller retained headers can admit more directories, but do not imply a lower WASM linear-memory high-water mark or whole-Worker peak. The cache cutover uses the new private HTTP path and R2 prefix without reading old frames; a missing or invalid artifact is rebuilt from the unchanged canonical header. R2 segment bytes and posting/document offsets are unchanged. Encoded directories have a nine-MiB pool: eight MiB for charged frames and one MiB for bounded access counters. The frame cache owns immutable Rust bytes and a private completed-validation proof. Its first successful decode verifies CRC and header semantics; later decodes of those same owned bytes reuse that proof while still checking inflation integrity, framing, lengths, binary structure, UTF-8, attribute JSON and the caller’s decoded-memory budget. Failed decodes cannot promote an unvalidated frame. Standalone decoding and new frame owners perform full validation. Synchronous cache consumers borrow the native frame and receive independently owned directories or copied bytes. Eviction and namespace invalidation release the native owner; acquired directories survive it. Admission charges retained native bytes and handle overhead within the existing pool. One MiB holds learned segment score bounds and another MiB holds compact text plans. Decoded-directory admission is twenty-nine MiB, and raw ranges/frequency pages retain twelve MiB, keeping these cache quotas at fifty-two MiB total. The forty-MiB individual decoded-directory validation limit remains; larger-than-admission directories remain scoped and uncached. Both encoded and decoded directory admission displace resident entries only when the incoming access count exceeds every required LRU victim count. Decoded hits advance the same bounded history as encoded-directory accesses. Counts saturate at 255 and halve every 4,096 directory accesses; cold counter entries disappear, and namespace invalidation clears retained entries and history. Up to sixty-four active source/header identities separately retain validated Rust handles while readers use them, including when cache admission rejects the object. A scoped SHA-256 fingerprint permits an identical copied frame to reuse that validated handle without parsing its JSON again. Both fingerprint and handle are released with the last reader. Concurrent readers share those handles; the last reader releases the temporary reference on completion or failure. A full active table keeps the ordinary acquisition path. These temporary handles have request lifetimes and do not extend cache retention or carry root, authorization or query-result authority. Canonical catalog recovery prepares physical attribute-group row indices and minimum lengths while encoding the reusable overview, then consumes them in the following catalog projection. This avoids grouping the same header twice. The prepared indices belong to the scoped Directory wrapper, not its shared Header; retained cache/active-reader handles start without them. Native heap reporting includes a live prepared group box, repeated overview encoding reuses it, and catalog projection consumes it even without filters. Scope disposal frees any preparation left by a failed projection. These groups change neither metadata serialization nor decoded-header cache quotas. Raw buffer charges include keys/entry overhead, while payload bytes remain separately reported. These are cache quotas, not a bound on active rankers, transient decoding or complete Worker peak memory. Cache identities keep the bucket/object prefix used by namespace invalidation, with a format suffix separating compressed directories from raw ranges. Document-range batching still tests raw-range identities, and in-flight acquisition sharing remains format-specific. Uncompressed ranges of at most 64 KiB give the complete cached binding fetch, including its body, a nominal 250 ms budget. Timeout sends an abort signal to that fetch and reads the same immutable range directly from canonical R2. A semaphore charges eligible acquisitions at four times requested bytes, rounded to 64 KiB units, against four MiB. Canonical fallback body reads settle before releasing permits; unused R2 bodies are canceled. The existing same-range Promise sharing covers both paths. Small-range quota admission uses nonqueued permits and one-millisecond native timer retries, preserving the original wait-for-capacity behavior and four-MiB charge without waiting on a foreign invocation's semaphore callback alone. Compressed directories and larger ranges keep the cached binding path without this fallback. Cache failures and invalid response lengths remain failures rather than timeout recovery. Health and metadata count timeout events, direct fallback attempts and transferred fallback bytes per isolate; these counters do not establish billed origin reads or total peak memory. Cancellation does not guarantee that a remote cache origin stopped an already-started read, so fallback may add an R2 request. Cache API and Worker Cache retain this derived representation without query-selector keys. Each immutable segment has a versioned, CRC-checked header and independently compressed, length-bounded, CRC-checked document/posting pages. Postings encode local row ids, title/body term frequencies and token positions with delta varints. Any/all scoring stores compact row/title-frequency/body-frequency lists; phrase scoring retains positional lists. Both readers validate every varint, including position ordering/overflow, CRC, decoded length and document-position bounds. After validating every decoded posting, the scorer retains only rows allowed by filters and tombstones. A separate per-term last-decoded-row map preserves block-order validation even when excluded rows are discarded. Unused JSON values are traversed without constructing value trees, while preserving number, string, nested structure and recursion validation. Cached masks remain keyed by the complete filter and tombstones remain query-local. Full term catalogs still supply global statistics and conservative score bounds. The shared scoring/cursor algorithm is monomorphized for each list representation, with no per-row dynamic dispatch. A lazy, request-local Rust PreparedQuery parses shared ranking input, normalizes words, sorts and deduplicates term indices, compiles BM25 scorers and records repeated-token phrase order once. Segment rankers share that immutable preparation; each selected segment still applies its own filters and tombstones. Its constructor requires an empty shared dead-row list, and the segment ranker receives the actual list separately. Native DisposableStack lifetime releases the plan on completion/error, while rankers retain the reference-counted immutable term preparation and remain valid after plan release. The plan retains normalized words, statistics, sorted indices, scorers, phrase order, mode, top-k and filters; original query text and the empty shared tombstone vector are released after validation. Segment eligibility and posting lists remain independently owned. No compiled query enters a process cache. Top-k scoring reserves its bounded heap once and replaces the worst hit only when a candidate wins the existing score/row comparison. Noncompetitive candidates do not enter the heap; the heap never needs a transient k-plus-one hit. A block directory stores ranges and conservative frequency/length bounds. R2 range reads acquire required posting pages and immutable byte windows containing selected result documents. Global top-k merges keep that range with its segment and score; materialization reads those pages directly, without reopening the directory or crossing a second JSON/WASM range-projection boundary. Reading a document refreshes an already-resident directory's LRU position without decoding or retaining an absent header. The storage-owned materializer assembles text and vector result rows in hit order. Each branch shares eight document read permits when all selected encoded frames total at most 64 KiB; larger selections retain four. Hybrid evaluation can execute both branches concurrently. ## Resource limits

HTTP JSON bodies are bounded to 1,900,000 bytes. A write accepts at most 1,000 upserts and 1,000 deletes. Duplicate ids across a batch are rejected. Rust log decoding is bounded to 2 MiB, including decompression bombs. Index segments are capped at 10,000 documents and 16 MiB encoded bytes, with independently bounded page decode. Text queries accept at most 100 results and 512 distinct normalized terms; phrases are capped at 64 tokens. Vector/hybrid top-k is capped at 50 by native full-metadata retrieval. Filters have at most sixteen conditions, each `in` list capped at 32 scalar values. The canonical namespace schema can configure vector dimensions from 1 to 4096, with a backwards-compatible default of 768. Writes and queries reject mismatches with 400, and dimension changes require reset. This extension awaits the complete gate. Compaction reads each selected segment payload in one bounded range and decodes live document pages from that buffer, avoiding one R2 call per document. A window has at most eight segments and 8 MiB of decoded documents.

One namespace is currently coordinated by one Durable Object; that object's memory is disposable. The R2 manifest and number of segments still need scale-bound validation. Sharded manifest directories, distributed BM25 statistics, export pagination, request rate limits and per-namespace credentials are not implemented. There is one deployment-owner API credential. This must not be advertised as a hosted tenant authorization system.

Readers cap envelope objects at two MiB, frames at one MiB and decoded frames at sixteen MiB; builders cap group/term entries at one quarter of vocabulary size, clamped to 512–65,536 entries. Singleton terms retain their ordinary physical bound in every group and add no partition entries. Expanded synopses exceeding this budget are omitted. Over-budget segments retain the ordinary path. Alchemy owns cache retirement through a thirty-day lifecycle rule, independently of canonical segment collection. No manifest, receipt, outbox or result row depends on the cache. `correlatedReads`, `correlatedHits` and `correlatedBytes` report native R2 cache acquisitions separately from logical posting range counters. A missing synopsis adds one unsuccessful cache lookup before canonical fallback; cache-loss behavior remains correct but need not retain its latency improvement.

The five-element derived overview stores singleton references separately from the shared bound-summary pool, using row/ID/offset/length tuples and decoding only selected facts. The reader rejects invalid selected references and the retired four-element frame. Verified singleton summaries carry a physical row, document ID and metadata-page range only after Rust decodes the actual one-row posting and checks its frequency and document-length bounds against the canonical header. These optional facts are part of the projected summary and retained query plan; a header-only overview cannot manufacture them. When every present query term has a complete fact, Rust reuses the prepared query scorers, applies tombstones, combines same-row scores in the normal term order and uses the existing UTF-16 ID tie order, avoiding directory and posting acquisition. Filters require the existing complete constant-attribute proof. Multiword phrases, mixed frequent terms and incomplete facts retain ordinary ranking. Missing or corrupt derived sources fall back to canonical data. The private catalog route, overview Cache API identity and R2 overview-batch prefix advance together; canonical Root and segment bytes do not change.

The 4 MiB L1 term LRU charges each term projection, field eligibility model and exact-filter minimum independently. Keys include the bucket, immutable segment key, header length, entry kind and term or filter selector. A projection retains its dictionary and shared length partitions atomically. A bounded eligibility projection first retains every physical attribute group for the sorted unique filter field set, with minimum title/body lengths per group. If joint cardinality exceeds admission, construction folds the retained groups into per-field scalar columns and continues accumulating minima there. Columns share the same total 256-value and four-KiB limits; construction reuses a scalar encoding buffer instead of allocating a string for every existing value. For each field, Rust applies every predicate on that field before selecting its minimum title/body lengths. The componentwise maximum of these per-field minima is a conservative lower bound for the full conjunction: the intersection is a subset of each field's eligible rows. A field with no matching value proves the conjunction empty; matching values in separate columns do not prove that a jointly eligible document exists. Such false positives only loosen pruning, and the ranker still applies the complete conjunction before top-k. Small joint models retain exact correlated eligibility. Changing only predicate values can evaluate this model locally through the same Rust filter matcher instead of requesting another catalog. Admission validates and encodes the model once; the L1 retains that immutable JSON string rather than revalidating and reserializing its scalar cells on every query. Rust resolves predicate field indices once per query and evaluates group vectors through the same scalar matcher, without rebuilding attribute maps for each group. Missing attributes and explicit null remain distinct; scalar values retain their original JSON encoding so Rust numeric comparisons survive transport. The scalar Schema memoizes only successful validation of encoded scalars at most 64 UTF-16 code units long, retaining at most 256 entries in insertion order. Invalid values and longer strings always run the complete decoder. Reuse stores validation truth only, never eligibility, authorization or query results, and does not change Schema rejection behavior. Models support up to sixty-four declared fields, while catalog selectors retain the sixteen-field query limit; joint groups or total column values remain capped at 256 and encoded models at four KiB; unsupported or oversized models fall back to minima keyed by the exact filter selector. All three entry kinds share the existing four-MiB budget. Models describe physical rows only: current tombstones, global statistics and exact filter checks still apply before ranking. Eviction removes an individual selector instead of every selector for a segment. Cache updates encode only the inserted value, without copying and re-encoding the segment's accumulated selector maps; cache hits only refresh LRU order. A dictionary is never combined with partitions from another projection. Projection selectors use the sorted Bloom candidates for each physical segment. A miss group requests the union of its needed terms; a Bloom-negative term is physically absent from that segment, so the union cannot introduce a real dictionary entry outside its selector. Changing only filters reuses the projection; changing only terms can reuse eligibility. Terms excluded by every segment Bloom are removed from non-positional execution and plan identity, while phrase order stays intact and all/phrase impossibility checks still run against the complete requested term set. Query-local references survive concurrent eviction. Missing parts are acquired in separate ordered groups: full projections, dictionaries without filters, or eligibility-only projections with zero terms. Groups run sequentially inside each window, with up to eight windows concurrent; final catalogs restore input order before live statistics are aggregated. The internal zero-term projection has a current eligibility-only consumer and does not change public text-query validation. Clearing immutable memory also clears these entries, while native/Cache API projections remain disposable shared layers. Global live frequencies are still recomputed against the selected root and its removed frequencies. All segments are prioritized by descending projected score bound and then ascending UTF-16 minimum id. Bounds use cached exact physical eligibility minima or conservative marginal lower bounds with fresh live statistics; deleting a physical candidate can only loosen this bound. A null minimum proves that no physical document satisfies the predicate and skips ranking, but that segment's dictionary still contributes to namespace-wide frequencies. Tombstones and filters remain exact in the ranker before top-k. No bound-only path acquires a full directory. Candidate ranking and result materialization acquire directories only when needed. Ranking windows with multiple eligible segments try validated R2 directory frames locally before the internal cache service. A missing or rejected frame follows the existing native-cache/canonical recovery path and can rebuild the disposable frame. The existing active-directory lifetime shares the acquisition outcome among concurrent R2-first readers. Successful direct reads enter the same bounded compressed-frame admission policy as native-cache responses; decoded-cache, body and reader quotas stay unchanged. Single-segment windows retain the native-cache-first path.

For strong reads, a manifest commit changes the live segment set and tombstones before query evaluation. Edge-eventual reads can observe pre-mutation rows within their explicit snapshot age bound; a minimumSequence barrier requires the acknowledged mutation. Cached old bytes therefore cannot restore removed rows. No purge is needed to keep mutations correct; immutable bytes can remain cached until eviction. Local workerd tests exercise Cache API, memory eviction, namespace separation and mutation reconciliation. Native Workers Cache, regional tiers and request collapsing require deployed evidence because the local emulator does not implement them.

R2 public custom-domain CDN caching, Smart Tiered Cache for public buckets, and Cache Reserve are separate Cloudflare capabilities. They are not enabled by an R2 binding or a `cache.put` call. The bucket remains private; this architecture uses the internal Worker cache path instead of exposing canonical documents through a public bucket domain.

Native cache smoke evidence recorded both Workers Cache hits and Cache API hits after clearing the volatile range/directory caches. The health endpoint measures its own serving isolate; coordinator metadata measures the Durable Object's isolate. Linear memory includes allocator high-water capacity and does not measure total V8/Worker heap. Encoded size equals the canonical compact object written by the engine; an empty, uncommitted namespace can have a virtual manifest with no stored object. These are operational diagnostics, not a billing meter. Computing encoded size occurs only on metadata reads, not on ordinary query acquisition. The local gate and executable negative lint probes are documented in the README. ## Vector metadata lifecycle

Native filter evaluation uses the canonical directory attributes for every declared filterable field before vector selection. No provider metadata indexes, scalar hashes or metadata pushdown are required. The legacy vectorFilterFields field remains accepted for stored-schema and cursor compatibility.

Every stack deploy runs the native Command.Exec vector validation without memoization. It inventories namespace prefixes through the authenticated paginated operator API and rebuilds vectors in batches of at most 100. Rebuild checkpoints store the immutable root view and field layout in R2, and cursors are validated. Resumed pages reconcile revisions, deletion and physical compaction against the current R2 root. A namespace reset or field-layout change rejects the old cursor. Validation reads canonical vectors without rewriting them, so retries preserve immutable state. Checkpoints store an absolute expiresAt timestamp in R2 custom metadata and initially remain available for seven days, including completed checkpoints. Root-format migration preserves each legacy checkpoint deadline as its original uploaded timestamp plus seven days; retries retain the persisted deadline rather than extending retention on rewrite. Expired cursors return 410 and require a new snapshot. Vector query visibility follows the committed Root and does not wait for this validation.

Historical Vectorize deployment evidence: The deployed metadata migration inventoried seven existing R2 namespaces and resubmitted two existing vectors. The deployment graph references complete native index outputs before supplying the field binding, and the migration references the complete Worker output before consuming its URL. Referencing the stable URL alone allowed migration to start against the previous Worker; the ordered resource references now own that dependency.

Bloom packs contain at most 64 immutable segment rows in adjacent document and term columns. Each column is limited to 16 MiB, with validated offsets, nonempty rows and its own SHA-256 digest. Queries group selected rows by pack and column, load canonical R2 ranges directly, verify their exact length and digest before native filtering or cache admission, and preserve selected segment order. Missing or corrupt bytes fail the query rather than claiming absence. Covered common terms and existing impossibility proofs skip these reads. In-flight column acquisitions share native Promise outcomes; admission polls within each request instead of retaining another request’s Effect scheduler. Four concurrent GETs and a weighted 16 MiB column-read quota bound this acquisition path, separately from the existing 4 MiB retained Bloom LRU. Health exposes isolate-local `bloomR2Reads` and `bloomR2Bytes`, which are not billing receipts. Appends rewrite only a partial immutable tail pack, or start a new pack when full; writes publish segments and verified packs before the Root CAS. Compaction preserves surviving references and may leave unused rows. Tail rewriting exclusively reserves the read admission budget but can retain a 32 MiB old pack alongside a 32 MiB replacement. That transient allocation is outside the 16 MiB column-read accounting. Tail rewriting adds a canonical read and immutable PUT, and obsolete packs remain until collection finishes its grace period. These limits do not bound total Worker RSS or establish a cost or latency improvement.

## R2 canonical object collection

`collect` runs under the namespace coordinator semaphore. Each invocation reads the active root, inventories rebuild checkpoints, then lists up to 100 Bloom packs and, once that phase completes, up to 100 segments. A versioned opaque cursor records the phase and native R2 cursor; legacy raw cursors are rejected. The active root, captured strong-reader manifests and every unexpired checkpoint pin their referenced segments and Bloom packs. Checkpoint inventory is bounded to 1,024 objects, 8 MiB per checkpoint, 32 MiB total checkpoint input and separate limits of 16,384 unique segment references and 16,384 unique Bloom pack references; exceeding a budget fails before deleting canonical objects. Expired checkpoints can be removed while inventory is built.

An unreferenced segment or Bloom pack gets a separate retirement marker with its key, ETag and observation time. Its original upload time does not start the quarantine: a segment may have been live until moments ago. A subsequent collection can delete the object only after 24 hours with the same ETag, an observation at least as recent as the object upload, and no current pin. A newer upload restarts the quarantine even when identical bytes preserve the ETag. Reusing an existing content-addressed Bloom pack first validates its size and full SHA-256 checksum, then removes its retirement marker before the root may reference it again. Marker-removal failure prevents publication; an orphan left by a later failed root CAS receives a fresh quarantine on collection. Replacement resets the quarantine, a future timestamp resets the observation, and a current pin cancels the marker. Deletion precedes marker removal, making interrupted deletion retries safe. Malformed markers and unavailable checkpoints fail closed. Derived retirement markers do not change the canonical root schema.

Edge text evaluation has a 30-second response deadline after snapshot selection; selection itself requires a snapshot younger than one second. The 24-hour retirement quarantine therefore covers those detached readers. Strong queries and rebuild pages serialize with collection and cannot race a physical deletion. The collector does not delete logs, receipts or old Vectorize epochs. It is an explicit operator operation; automatic scheduled collection and Vectorize epoch reclamation remain outstanding.

## Bounded independent query reads

Filtered Root-bounded queries with a missing retained plan prefer validated immutable R2 directory frames for singleton ranking batches as well as parallel batches. This removes duplicate segment-origin range acquisition when a frame exists. Missing or corrupt frames retain canonical recovery and may add a bounded directory probe; no scheduling or ranking policy changes.

Text evaluation loads candidate segment dictionaries with at most eight concurrent batch reads, then computes global live document frequencies in manifest order. An isolated native cold-summary comparison found no latency benefit from reducing that limit to four; two and one were slower. The measured decision is recorded in [performance](performance.md#native-cold-catalog-concurrency). Within each batch, immutable catalog memory hits are retained and touched independently; only missing ranges enter the internal Terms request. Returned catalogs are merged by original batch position before live frequency aggregation, including when cache admission evicts another query-local hit. Exact segment score bounds are evaluated in batches of at most 64 catalogs, decoding the shared namespace statistics once and constructing each encountered term's BM25 scorer once per batch. The temporary scorer map borrows catalog keys and is dropped with the batch; block maxima and eligible field-length minima remain segment-specific. The returned bound count and finite values are checked before priority sorting. Only competitive segments acquire the full posting directory from the Rust directory already loaded for ranking. Offsets, first/last rows and block counts are absent from the cached score projection. Score projections retain only unique field-frequency maxima and field-length minima tuples per term. Their order and multiplicity have no scoring meaning: segment bounds take the maximum over those tuples. Document frequencies, eligible filter minima and the canonical posting/block directory remain unchanged. Derived catalog cache versions change with this projection; no R2 migration is required. Within each scored segment, requested term spans are grouped in their original order. Coalescing admits at most 16 KiB of additional gaps per group and a combined range of at most 1 MiB; larger individual spans retain their existing segment bound. Up to four grouped ranges are acquired concurrently. The reader validates ordering, gap/size budgets, positive lengths and segment bounds, then passes only the selected subarray slices to Rust in the original block order, preserving the strictly increasing row invariant. Gap bytes are transferred and charged but never decoded as postings. Final hit documents also load with concurrency four and preserve ranking order. Within each Rust segment ranker, exact block bounds are prepared lazily when top-k first fills and reused for subsequent pruning. Block selection remains the original linear first-match lookup and bounds are summed in sorted term order; the cache belongs only to that finish operation. Any-mode candidates begin with union traversal. Once top-k fills, the cursor computes each term's maximum conservative block score and selects the largest upper bound, preferring the shorter posting list on a tie. If the cutoff strictly exceeds the sum of every other term's upper bound plus the existing tolerance, every competitive remaining document must contain that term. The cursor then uses its posting list as a driver and seeks the other lists to each candidate before scoring. The cutoff never decreases, so the requirement remains valid for the rest of that finish operation. Sorted-term score accumulation, equal-score ID ordering and posting validation remain unchanged. All/phrase candidates use the shortest posting list as a driver, skip excluded driver rows before alignment and seek other lists with adaptive exponential/binary search. A terminated list ends the intersection. When every list covers every physical document, row positions coincide with their indices; cursors synchronize only after excluded rows cause divergence. Valid candidates retain the original sorted-term score accumulation and repeated-token phrase order. Each planned segment carries an upper match count from live physical document frequencies: any uses their sum capped by live documents, and all/phrase use their minimum. Attribute filters can only reduce those counts; no eligible attribute group gives zero. Invalid live cardinalities fail rather than being clamped; DF lookups use own record entries through native Maps, including ordinary terms such as `constructor`. Initial candidates may run together when their combined ceiling cannot exceed the missing top-k slots, because no still-possible hit can be pruned by an earlier cutoff. Otherwise the first prioritized segment runs alone. Later windows retain the original four-position boundaries and admit at most four segments. An incomplete top-k caps its next window by the number of missing result slots when the previous window returned matches; a window without matches retains parallel exploration. A complete top-k retains sequential evaluation through the first four candidate positions for early pruning. A four-permit limit is shared across directory and posting acquisitions. Each window uses the cutoff from the preceding completed window; its results merge in stable score/ID order before the next window. At most four grouped ranges per segment are acquired together. Four retained rankers and four in-flight reads are per-query limits, not a total Worker memory bound. No query-result caching is introduced. Cold concurrent workerd requests are checked against the strong scorer for identical IDs, revisions and scores.

Query responses expose request-scoped Server-Timing for dictionary acquisition, ranking/posting acquisition and result-document acquisition. Edge responses additionally measure snapshot selection; coordinator and gateway totals are retained. These are elapsed intervals, including I/O, rather than CPU measurements. `tooling/load.ts` records each response's timings alongside its latency samples without deriving per-request statistics from shared counters.

The benchmark bucket's recorded physical location is `enam`. Cloudflare currently lists R2 hints for western/eastern North America, western/eastern Europe, Asia-Pacific and Oceania, and does not list a South America hint. Hints apply at creation and are best effort; a bucket's existing location cannot be relocated by updating its hint. This is a deployment constraint, not proof that geography explains every measured delay. See [R2 data location](https://developers.cloudflare.com/r2/reference/data-location/). Cloudflare also documents that Durable Objects hinted to `sam` currently spawn in eastern North America and existing objects do not relocate. A location hint therefore cannot remove the coordinator hop by placing this existing object in Brazil; this constraint is separate from gateway and R2 placement. See [Durable Object data location](https://developers.cloudflare.com/durable-objects/reference/data-location/).

Warm edge namespaces retain decoded snapshots in an isolate-owned LRU before using Cache API. Entries keep their original R2 observation timestamp; neither a memory hit nor Cache API rehydration extends freshness. The cache is capped at 24 MiB of conservative charge, using four times the encoded UTF-8 size per snapshot; oversized snapshots bypass this layer. Namespace and bucket identity stay in the key. Invalid ages and insufficient sequence barriers trigger fresh R2 acquisition. The LRU may retain an expired snapshot with its R2-sourced ETag as a conditional-read candidate; it is never eligible for ranking solely because it remains in memory. A native conditional get confirms an unchanged ETag without a body, then establishes a new observation timestamp measured before that read. Changed content is fetched and fully decoded. Cache API rehydration retains a previously R2-sourced ETag and publication-attempt timestamp only when the validated cached payload matches the prior sequence, byte length and complete bytes. Native [timingSafeEqual](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/#timingsafeequal) compares the equal-length views, including their offsets. Cache response headers never supply origin provenance. A missing origin or different payload still requires a full R2 read on the next refresh. Rehydration keeps the cached frame's own observation timestamp; preserving an ETag never extends that lease. The same age and sequence checks apply after either acquisition path. `edge_snapshot_revalidated` marks foreground conditional-read confirmation, and health counters report body bytes and confirmations. Strong reads never use either snapshot cache. Cache API remains the shared data-center layer. Snapshot responses carry the original observation time and manifest sequence in validated headers, so missing metadata, expired/future ages and insufficient sequences discard the body before JSON decoding. An eligible body still undergoes full Schema validation and the original age/sequence checks. Headers never extend freshness or authorize a stale body. Per-request `edge_snapshot_cache_rejected` marks this early rejection; health counters expose snapshot decodes and header rejections. Immutable segment ranges retain the native Workers Cache regional tiers.

Vector synchronization still processes version-specific deletions, but only submits upserts whose epoch and revision remain live in the canonical R2 root. Superseded jobs are acknowledged without allocating obsolete provider vectors. The indexed-field configuration is decoded once per synchronization operation. This removes unnecessary mutation and storage work; it does not reclaim vectors that an older provider mutation already made visible before the revision changed.

Result materialization groups hits by immutable segment key, header size and total size, then orders their byte offsets into batches of at most eight pages, with a one-MiB span and at most 64 KiB of unrequested gap bytes. Overlapping pages and over-budget spans retain ordinary page reads. When every exact frame is already in the byte cache, validated pages decode directly in input order through the existing native integrity checks and StoredDocument Schema; cache hits update the same range LRU and counters without asynchronous admission. Mixed hits and misses retain the ordinary semaphore-controlled page reader. Only requested frames are decoded; their original hit indexes restore ranking order, duplicate hits and complete document payloads; sparse union bodies stay outside the application range cache, while the native Worker Cache and Cache API may retain them. Pending acquisitions distinguish application retention policies. Sparse spans use the existing byte admission and bounded canonical recovery, including spans above the ordinary small-range threshold.

## Bounded Queue batching

Vector consumers receive up to sixteen messages per batch, index consumers up to eight, with a one-second batching window and at most four native consumer invocations. The Worker processes at most four messages concurrently. Namespace Durable Object semaphores retain serialization of canonical mutations. These are separate concurrency limits, not a claim of sixteen-fold throughput.

A validated vector notification drains up to sixteen canonical jobs, rather than only its own sequence. Only a notification still referenced by the canonical root may trigger that drain; duplicate or retired notifications submit zero jobs. Log identity and namespace are checked before dispatch. Upserts and version-specific deletions share bounded buffers across the selected jobs, flushing at 100 entries and committing the root only after all provider submissions succeed. Live revision/epoch checks prevent superseded jobs from allocating provider vectors. Provider failures retain the outbox and replay deterministic identities.

Every queue message owns its acknowledgement or retry, including decode failures and failed binding calls. A malformed message retries without cancelling a healthy sibling. Response bodies are consumed before acknowledging. Dedicated dead-letter queues remain provisioned.

## Query encoding and cache decisions

Empty filters bypass filter-mask key encoding and lookup. A hit clones the packed mask without allocating a second all-true mask. Tombstones clear only the query-local copy, so cached eligibility remains tied to immutable attributes. Representative evaluation and masks share the directory reservation described above; packing does not increase that reservation or change serialized formats.

The original term order, the sorted projection selector, filters and global statistics are each encoded once per text query for their repeated consumers. Each ranker still receives its own tombstones. The candidate array is already sorted after each segment merge, so no duplicate final sort is performed. Exact score bounds, returned rows, snapshot age and authorization remain unchanged.

A twelve-query cold local regression observed thirteen immutable range reads, the same as one query in that fixture; ten isolated repeats also passed after switching to physical bucket identity. That full-query evidence alone did not justify another acquisition owner. A later direct range-boundary test demonstrated duplicate body consumption despite native collapsing; pending-only sharing now addresses that separate cost, as documented above. Native deployment still has cold directory-acquisition tails; local cache efficiency does not establish regional latency guarantees.

Workers KV was evaluated for mutable snapshots and immutable derived data. Its documented propagation and negative-cache delays can exceed sixty seconds, incompatible with this engine's less-than-one-second snapshot contract. Immutable bytes already have native Worker Cache tiers and local Cache API ownership; another KV copy would introduce a read/write path without demonstrated benefit here. R2 remains canonical, with no new stateful dependency. See [KV consistency and caching](https://developers.cloudflare.com/kv/concepts/how-kv-works/) and [Queue batching and retries](https://developers.cloudflare.com/queues/configuration/batching-retries/).

Posting telemetry keeps request-local elapsed intervals for directory/ranker preparation, acquisition windows, Rust block decode and scorer finalization. Server-Timing descriptions include logical spans/bytes, decoded blocks and scored segments. Spans count selected term spans, ranges count grouped acquisitions, and bytes include admitted gaps. These counts include memory/shared acquisition reuse and do not equal R2 origin calls or transfer. Native clocks can remain unchanged during uninterrupted CPU work; zero durations are not CPU measurements.

Query Schema decoders, encoders and namespace/operation guards are created once per isolate. Effect retains the compiled parser on each native adapter; constructing a new JSON Schema and adapter for every segment discards that identity. Request data, validation options and results remain query-local. Two alternating local comparisons over 50,000 documents and 100, 30 and 8 segments checked 2,688 identical responses, including exact scores and sequence barriers. Rare-query medians improved by 8–28%; common-query medians improved by 2–18%. Some filtered/phrase cells regressed by up to 18%, so this is not a uniform latency guarantee or evidence of production improvement.

The native production CPU profiler can identify work that elapsed request timers miss. A ten-second capture under concurrent queries contained Schema compilation and guard construction alongside Effect execution, JSON parsing, cache publication and Rust frames. Source mapping must match the deployed bundle exactly; samples describe one selected isolate and include idle time. They do not establish billed CPU or request percentiles. The corresponding heap capture returned no allocation samples and cannot establish retained or peak memory. See [Cloudflare production profiling](https://developers.cloudflare.com/workers/observability/profiling-in-production/).

Queries with more than four candidate segments may retain conservative ranking bounds in a one-MiB process LRU. Each bound pairs an upper score with the smallest possible ID at that score, using the same UTF-16 order as the Rust scorer. Selection identity hashes Schema-encoded normalized text, mode, filters and live global statistics; top-k is normalized to one, while physical bucket, immutable key, header length and tombstone rows additionally scope each entry. The upper score covers both returned hits and the external cutoff used to omit pages. At an equal cutoff score, omitted blocks cannot contain an eligible ID before the cutoff ID; returned hits can tighten that minimum, and a higher returned score replaces both components. With no external cutoff, the physical source minimum starts the certificate. The ID bound applies only at the upper score: lower-scoring rows can have earlier IDs. Cache updates retain the tighter certificate, preferring a lower upper score or a larger minimum ID at equal score. Planning combines it with the catalog bound, prioritizes the same score/ID order and preserves the existing numeric pruning tolerance. A retained zero upper score makes the segment ineligible with a zero match ceiling: the scorer returns only positive scores, and external cutoffs are included in the certificate. Requested top-k does not change certificate validity. Current canonical manifest acquisition, authorization and minimumSequence checks remain authoritative; no result rows or root authority enter this cache. Charging includes the key, retained ID and entry overhead, with LRU eviction and namespace rebuild invalidation. Health/metadata expose retained charge and entry count, not whole-Worker peak memory.

A separate one-MiB process LRU retains compact text plans for selections with more than four candidate segments. A plan contains computed global statistics and aligned per-segment eligibility, ranking bounds and match-count ceilings, without term dictionaries, rows or native handles. Its identity includes physical document counts as well as immutable keys, header lengths and tombstone metadata; tightening a score bound retains the match ceiling. Its identity hashes Schema-encoded Rust-normalized tokens, mode, filters, current live document/title/body totals and every selected segment's immutable key, header length, physical minimum ID, tombstones and removed frequencies. Any/all identities sort and deduplicate the normalized tokens; phrase identities retain their order and repetitions. Learned segment maxima use the same normalized text identity. The original request text still reaches the Rust ranker. The physical bucket and namespace/object prefix scope the cache key. No manifest sequence or object-reference shortcut substitutes for this content identity: compaction may change segments without changing sequence, and a document outside selected segments can still change global scoring totals. Current manifest acquisition, authorization and minimumSequence checks precede planning. On a hit, current segment objects receive the retained eligibility/bounds; learned score bounds remain separately scoped to exact scoring inputs. Top-k does not change plan validity. Missing, evicted or oversized plans use the original catalog path. Entry charge includes four times encoded plan length and key length plus entry overhead; namespace rebuild clears the plan entries. This reallocates one MiB from encoded directories while preserving the fifty-two-MiB cache quota sum and does not establish total Worker peak memory. Metadata/health report plan charge, entries and process-local hits.

Completed text plans can recover through the native Cache API after isolate memory is lost. Their key includes the same complete current selection identity plus Cloudflare's native Worker version ID from `CF_VERSION_METADATA`. The version binding is provisioned by Alchemy; no manual engine-version setting or cross-deploy scoring reuse is used. After ranking, each segment's original catalog certificate can be tightened with a learned score/ID certificate; omitted pages remain covered by the external cutoff. Unranked segments retain their original safe bound. Memory retains the tightened plan immediately. A new or improved plan is offered as a compressed Rust CRC frame with a one-hour cache lifetime through the owning HTTP or Durable Object context’s native `waitUntil`. Publication does not delay row materialization or query completion. Canonical R2 segments and manifests are unchanged.

Shared-frame admission caps encoded JSON at one MiB and compressed bytes at 256 KiB. Concrete Schema-encoded headers declare both lengths. Read admission charges the larger of compressed size and four times declared inflated size in 64-KiB units against a four-MiB target. Readers require exact agreement between headers, actual compressed bytes and the native frame length before unpacking, verify Rust framing/checksum/decompression limits and the concrete SharedTextPlan Schema, then require matching selection identity, Worker version, segment count and current document/title/body totals. Invalid, missing or unavailable cache entries recover through catalog acquisition. Namespace rebuild clears process memory; it can then safely rehydrate an immutable shared plan for unchanged canonical inputs. Tests simulate the same deployed version across fresh workerd instances with a stable native-shaped version fixture; production uses Cloudflare's actual binding. Server-Timing reports request-local plan provenance (`bypass`, `memory`, `shared`, `miss`) and learned-bound hits. Responses report `text_plan_publish_scheduled` when publication is admitted and `text_plan_publish_skipped` otherwise; neither marker proves storage success. Text-plan, ANN-candidate and immutable overview-batch publications share one process-owned admission owner in storage. Overview batches carry their bucket, ordered immutable key/header-length references and complete overview bytes. The v6 Cache API representation is JSON; the same envelope is packed into a CRC-checked Rust frame for the R2 backstop. Batches of eight or more sources use namespace-scoped `cache/correlated-pool-batches-v1/<first-source-key>/<ordered-range-digest>` objects, covered by the existing correlated-cache lifecycle. After memory and Cache API misses, R2 batch lookup has a nominal one-second shared outcome and at most sixteen pending sources. The pending entry remains until the actual native source settles, including after foreground timeout; the owning Terms context observes it through waitUntil. Batch body admission uses non-queuing semaphore attempts with exponential retries starting at one millisecond and capped at sixteen milliseconds. A one-second lookup/admission deadline skips late acquisition or decoding, while nonabortable body consumption retains its quota until settlement. Size, declared length, frame length/CRC, bucket, ordered references and overview count must agree. A hit repopulates memory and schedules Cache API promotion; misses, unavailable admission and invalid frames recover through individual correlated summaries and canonical directories. Both encoded and declared decoded batch sizes are capped at 512 KiB. Overview batches are published through their acquiring Terms context or the namespace Durable Object after a committed write or compaction. Segment publication retains derived overview bytes in the existing four-MiB memory cache. ### Exact uniform term scoring

Rust may compute exact BM25 scores directly from immutable segment headers when every requested term covers every physical row, with contiguous complete blocks and one occurrence in the same field per term. Metadata guards bound document counts, block sizes and byte ranges, require positive lengths for used fields, and reject unsupported frequency patterns. The Worker performs the proof before fetching posting spans and retains shared decoding, learned bounds, merging and cleanup. `text_uniform_hits` reports shortcut segments; preparation timing includes proof computation.

Within each uniform evaluation, sixty-four stack-local slots reuse scores for exact title/body length pairs. Query terms, term frequencies and scorers stay fixed for that invocation. This adds no retained heap cache or cross-query state. The component benchmark measures reused-directory ranker construction, result production and release; it does not measure a complete cold query.

This is a canonical-header trust boundary, not independent validation of unfetched posting bytes. It changes neither the segment format nor R2 ownership.
