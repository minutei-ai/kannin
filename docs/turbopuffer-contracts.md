# Turbopuffer compatibility contract

Full drop-in compatibility with the public Turbopuffer API and documented behavior is the target as of 2026-10-26. Similar architecture, a translated query subset, or matching latency alone does not satisfy it. **Kannin is not currently compatible.** Its shipped interface remains the native API documented in [api.md](api.md), with the Effect binding in [sdk.md](sdk.md). Existing local correctness and performance checks do not certify Turbopuffer compatibility.

The target includes request/response shapes, defaults, validation, errors, limits, ordering, mutation atomicity, read visibility and every documented feature. Official clients must work by changing the base URL and credential, without caller-side translation. Native binding consumers must reach the same domain operations and semantics; HTTP is not introduced between Workers. No feature is marked supported because a parameter is accepted but ignored.

## Implemented conformance boundaries

The public HTTP error envelope now includes the required `status: error` member alongside its message, preserving the numeric HTTP status. Query, coordinator, gateway and administrative-list failures use the owning ErrorBody Schema. Administrative listing catches native acquisition and namespace-validation failures, logs the original failure and returns a sanitized, private/no-store 503. The native binding RpcReply/Rejected wire contract is unchanged.

At gate074, the independent six-request probe accepted every error envelope while the five unsupported operation routes returned 404. This historical probe proves envelope shape only. Namespace listing is now implemented separately; the other probed operation families remain unsupported.

`GET /v1/namespaces` now implements prefix filtering, page sizes from 1 to 1,000 (default 100), continuation cursors and the published response shape. Cursors are bound to the bucket and prefix. The native Effect SDK exposes the same domain operation as `namespaces` through the Worker binding. Listing consumes one R2 catalog page rather than reading every namespace Root. The first listing per native bucket binding also checks a persistent migration-completion marker; it returns 503 until the unconditional Root migration has backfilled existing namespaces and completed activation. See [the catalog lifecycle](architecture.md) for publication, recovery and the current administrator-token boundary.

The actual official TypeScript SDK 2.12.0 successfully iterates 1,002 local namespace IDs with page size 37 in 28 requests, without missing or duplicate IDs. Separate checks cover default 100, maximum 1,000, the final two entries, an absent prefix and a typed 401 APIError. All 33 SDK requests target loopback; zero hosted competitor requests were made. The dataset includes 1,001 locally seeded canonical Roots and catalog entries plus one real acknowledged native write. This proves this bounded listing contract, not the full namespace identity range, role-specific permissions, deletion/recreation or the other public operations.

A focused official-documentation check on 2026-10-29 narrows two schema/filter questions for the next domain cutover. The [write guide](https://turbopuffer.com/docs/write) declares signed 64-bit `int` and unsigned 64-bit `uint`, nullable attributes, inference from their first occurrence, and null defaults for attributes added after existing documents. The [query guide](https://turbopuffer.com/docs/query) states that `Eq null` selects missing attributes and `NotEq null` selects present attributes. These documented rules do not prove hosted treatment of explicitly stored null, all-null inference, JSON integer transport beyond JavaScript's safe range, or identifier ordering. The native legacy value model remains unchanged; public typed values and predicates must implement these rules in their canonical owners before the public codecs can claim support. The Rust range predicate replaces its former blanket `f64` conversion with exact signed/unsigned integer comparison and exact mixed integer/float ordering. Its tests cover adjacent values above 2^53, i64/u64 endpoints, fractional and subnormal values, signed zero, and serialized segment filtering before top-k. Legacy equality and the persisted value representation are unchanged. This exact range-comparison change passed the [complete gate at `a7fc13f`](https://github.com/minutei-ai/kannin/actions/runs/40952360839). It does not expose public typed attributes, IDs or lossless mutation replay.

The [official full-text guide](https://turbopuffer.com/docs/fts), checked on 2026-10-29, supports both `string` and `[]string` full-text attributes and identifies the open-source [alyze analyzer](https://github.com/turbopuffer/alyze) as the implementation behind default `word_v4`. Source inspected at [`016465ad`](https://github.com/turbopuffer/alyze/tree/016465ad431aaae388bf91b03e2afb516952a946) declares crate version 0.2.0. The [official Cargo index](https://github.com/rust-lang/crates.io-index/blob/master/al/yz/alyze), checked on the same date, lists 0.2.0 as published and not yanked, requiring Rust 1.88. Optional CJK dictionary features are disabled by default. Named full-text design must cover array attributes, position gaps after filtering, tokenizer configuration and per-field statistics rather than reuse native accent folding or silently skip arrays. The candidate engine now depends on alyze 0.2.0 and provides a bounded `word_v4` Rust/WASM analysis primitive with reusable buffers. Its resolved analyzer configuration owns stopword and stemming languages independently; a future public schema codec must resolve the public language and enable flags into that configuration. The primitive preserves input indices, raw UTF-8 spans and positions after filtering; its JSON boundary caps input at 2 MiB and output at 65,536 tokens. Native normalization and segment bytes are unchanged. The primitive passed native, WASM and workerd cases in the [complete gate at bcec737](https://github.com/minutei-ai/kannin/actions/runs/40914020500). This is not named-field indexing or public full-text support; per-field postings and statistics, public schema/write/query codecs and ranking conformance remain required gates.

At that pinned source revision, [the analyzer API](https://github.com/turbopuffer/alyze/blob/016465ad431aaae388bf91b03e2afb516952a946/src/analyze/mod.rs) emits token positions, byte ranges and input indices; filtered words still consume positions. Its [length filter](https://github.com/turbopuffer/alyze/blob/016465ad431aaae388bf91b03e2afb516952a946/src/analyze/filters.rs) counts Unicode scalar characters. These facts must inform posting positions and array-boundary tests. The upstream [WASM binding manifest](https://github.com/turbopuffer/alyze/blob/016465ad431aaae388bf91b03e2afb516952a946/wasm/Cargo.toml) enables the `getrandom` WebAssembly backend explicitly. This is source-level integration evidence, not a successful Kannin WASM build or proof of hosted tokenizer parity.

The current official full-text playground documents `max_token_length` in characters from 1 to 255, matching the inspected analyzer’s scalar-character length filter. The installed 2.12 SDK types describe bytes and a maximum of 254. The engine primitive uses the current documented character limit; this discrepancy must remain explicit in public schema conformance rather than silently claiming those SDK descriptions are equivalent. Stopword removal is documented as unavailable for Arabic, Greek, Romanian, Tamil and Turkish; the candidate primitive rejects those stopword configurations instead of ignoring them.

A focused [write-contract check](https://turbopuffer.com/docs/write#distance_metric) on 2026-10-29 confirms dense metrics are `cosine_distance = 1 - cosine_similarity` and `euclidean_squared = sum((x-y)^2)`, with lower distances preferred. The candidate Rust/WASM ranker implements both explicit modes in the existing selection owner, including raw-frame magnitudes and Euclidean origin vectors, while retaining descending cosine similarity for the native constructor. Eleven native vector tests cover closed-form distances, an independent exhaustive top-k oracle, insertion-order independence, invalid-frame atomicity and float32 extrema; native all-targets Clippy also passed. New WASM conformance cases and the complete gate are pending. This does not yet accept public metric declarations or change canonical namespace schemas, frame validation or API routing; persisted metric configuration and metric-aware zero-vector writes are required before public metric support can be claimed.

## v3 findings and implementation direction

The [public v3 log](https://turbopuffer.com/v3) describes a storage-engine redesign, not a new `/v3` API specification. Its [architecture introduction](https://turbopuffer.com/blog/rip-vector-database) makes ANN a secondary index rather than the primary address for document storage. Public updates describe columnar storage, constant/dictionary/run-length/frequency encodings, predicates evaluated on compressed representations, and batching retained through reads, filtering and scoring. The log also overlaps corpus-statistics acquisition with postings/filter reads for cold FTS and uses dynamic top-k pruning for attribute ordering. The grouped-count and FTS improvements are workload-specific; the published table still contains regressions relative to production. None of those numbers is a Kannin benchmark. Unpublished design details remain unknown.

These findings support a shared typed column/storage owner for projection, filters, sorting, aggregation and lexical indexes, with stable document identity independent of vectors. Existing metadata/vector separation, dictionary encoding, batching and constant proofs are useful building blocks, not evidence that this architecture or API is already implemented. Any persisted cutover needs one explicit migration, matching snapshot/cache identities and checkpoint/GC pinning. Do not bolt independent per-feature copies or a second canonical store onto the current fixed title/text model. R2, TypeScript/Effect, Rust/WASM and serverless execution remain the project constraints.

The October 26 [vectorized execution article](https://turbopuffer.com/blog/fully-vectorized-search-engine) adds an important boundary: operators exchange batches throughout execution, rather than converting storage batches back into individual rows. It connects filters, ranking signals, aggregation and projection through that common execution model. For Kannin, this motivates measuring materialization and dispatch between operators alongside storage reads; Rust or SIMD alone does not establish an equivalent pipeline. The article describes vectorized block-max MAXSCORE and partition-oriented vector scans, but does not publish a complete implementation or a new API contract. Keep these as implementation references, independently from public API conformance.

A name-boundary refresh on 2026-10-29 confirms a discrepancy: the [limits table](https://turbopuffer.com/docs/limits) specifies 128 bytes per attribute name, while the [write guide](https://turbopuffer.com/docs/write) says 128 characters and excludes a leading `$`. The native name extension adopts the 128-byte UTF-8 bound and the reserved-prefix rule, with canonical restart/filter tests on R2 and S3 passing the complete gate at `3f56aa6`. No hosted competitor probe resolves the wording difference. Typed schema inference/evolution, the 1,024-name namespace boundary and the public write/query wire contracts remain unimplemented.

A focused limits refresh on 2026-10-28 confirms a published maximum of 10,752 dimensions per dense vector and eight vector columns per namespace. The pending native dimension extension adopts that per-vector bound, while retaining one column and requiring an explicit namespace dimension declaration. This does not implement the remaining schema, inference, column, metric or public-wire contracts. [Current limits](https://turbopuffer.com/docs/limits).

## Conformance and delivery gates

1. Pin public sources and inventory complete wire and semantic contracts, including error/default/boundary behavior. Refresh source changes explicitly rather than silently chasing a moving branch.
2. Exercise official SDKs against local Kannin using only base-URL/credential changes. Separately validate raw requests/responses; SDK deserialization alone is not proof that every field or semantic rule is valid. Include direct native-binding consumers of the same operations.
3. Implement complete schema/identity/storage and mutation boundaries, then filters, ranking/projection, aggregation and namespace lifecycle. Preserve authorization, restart, concurrent-write and failure behavior in each cutover. No ignored parameters or success-shaped placeholders.
4. Run exhaustive/closed-form local oracles where the public semantics permit, and contract fixtures for every supported operation and expression. Cross-provider differential tests and hosted performance comparisons still require the owner’s separate explicit approval.
5. Pass the repository gate and comparable latency/RSS/heap/quality/capacity checks at the scope being claimed. Global parity remains incomplete until every required row has authoritative evidence.

Conditional document predicates, attribute ordering, aggregations, branching, automatic namespace sharding and the complete Turbopuffer API are not implemented. ## Cloudflare AI Search as a second reference

Turbopuffer remains the primary target. AI Search is a competing managed service, not a Kannin dependency. Its public documentation was reviewed on 2026-10-21. Live benchmarks against either competitor are deferred until Kannin is ready and the project owner explicitly approves them; the owner has authorized local correctness and before/after cold/warm/RSS validation with one executor capped at two GiB. No AI Search latency, quality or cost advantage has been measured here.

AI Search already combines BM25 and vector retrieval with fusion and metadata filtering before retrieval. Those capabilities overlap with Kannin and do not establish differentiation by themselves. AI Search manages parsing, chunking and indexing, returning scored chunks; Kannin's API accepts documents and caller-produced vectors. [Pipeline](https://developers.cloudflare.com/ai-search/concepts/how-ai-search-works/), [hybrid search](https://developers.cloudflare.com/ai-search/configuration/indexing/hybrid-search/) and [filtering](https://developers.cloudflare.com/ai-search/configuration/retrieval/filtering/).

A focused refresh on 2026-10-22 confirms parallel vector/BM25 retrieval, default RRF fusion, optional normalized-max fusion and optional cross-encoder reranking. Keyword indexing offers Porter or trigram tokenization and AND/OR matching; changing the tokenizer triggers reindexing. Trigram cannot match standalone terms shorter than three characters. Tokenizer and chunking differences must therefore be accounted for in relevance comparisons. Kannin already runs its lexical and vector branches concurrently and fuses hybrid results by reciprocal rank in the query owner; this overlap is not a new optimization opportunity. [Keyword search](https://developers.cloudflare.com/ai-search/configuration/indexing/keyword-search/) and [hybrid search](https://developers.cloudflare.com/ai-search/configuration/indexing/hybrid-search/).

The current Paid limits are 500,000 files per keyword/hybrid instance, five custom metadata fields and a filterable string prefix of 64 UTF-8 bytes. Files are not interchangeable with Kannin documents or indexed chunks. Published billing starts November 1, 2026: excess full-text queries cost $0.10 per 1,000, semantic/hybrid queries $0.75 per 1,000, index storage $2 per GB-month and base ingestion $0.75 per million tokens. Included allowances and Workers AI embedding/reranking coverage matter when comparing total cost. The GA announcement also identifies large-store keyword scaling as ongoing work; it supplies no measured Kannin advantage. [Limits and pricing](https://developers.cloudflare.com/ai-search/platform/limits-pricing/) and [GA announcement](https://blog.cloudflare.com/ai-search-ga/).

The documented AI Search request has no namespace commit barrier equivalent to `minimumSequence`. ## Cost reductions with observable behavior

Immutable range coalescing reduces R2 calls without changing exact scoring. Bounded warm caches reduce repeated object transfer and decoding; Cache API is local to the serving data center and may evict entries, as described in [Cloudflare's Cache API contract](https://developers.cloudflare.com/workers/runtime-apis/cache/). Every cache miss retains an R2 path, and authorization stays outside shared HTTP caches.

Root v3 also pools bounded native eligibility models over the namespace's explicitly declared fields. Covered text queries evaluate their field subset against those facts and retain correlated native score bounds without catalog RPCs. Unsupported models or uncovered terms use canonical catalogs; exact filters and tombstones still apply before top-k. The current integration's final gate and artifact comparison are pending. Earlier private experiments motivate this path but do not establish production latency, billed R2 savings or parity with either managed service.

Vector synchronization now skips obsolete revisions and retired epochs, validates live persisted vectors against committed logs and acknowledges successful jobs through a conditional Root commit. Queries do not wait for this validation and no external vector allocation occurs. Segment collection still quarantines retired objects; durable logs and receipts remain retained. Native-vector validation is pending, and actual costs depend on object storage, CPU, coordination, queues and cache behavior.

Reproduce the gate with `bun run check` and the local measurement with `RAIO_BENCH_DOCUMENTS=100000 bun run bench`. Ranking quality has its own [dataset and methodology](quality.md).

The native queue regression checks that one workerd service-binding delivery validates sixteen committed canonical jobs and acknowledges them through one owning Root commit; a seventeenth job remains pending. Duplicate delivery validates zero jobs. A corrupt log fails without acknowledging its canonical outbox job, allowing retry. These cases await the complete native-vector gate and do not measure indexing throughput.
